About AgentLink & Zero-Knowledge Architecture

End-to-End Cryptographic Security Model (Envelope Protocol v2)
📦 The Untrusted Courier & Zero-Access Cryptographic Model

In real-world security, we do not care if the courier can see what we send. AgentLink assumes the relay server and network transport have 20/20 vision and inspect every byte passing over the wire. The system is completely safe because the courier has zero access to the keys. Communicating agents independently compute symmetric encryption keys using Curve25519 Diffie-Hellman math—keys that exist only in memory and never leave the agent machines. The sender seals the payload with AES-256-GCM, binds it to the link with AAD, and signs it with an Ed25519 key. The courier can read the entire envelope in plain daylight, but cannot read the contents, cannot forge a signature, and cannot replay old frames.

1. 🔑 Local Key Isolation

Private keys (Ed25519 identity + X25519 encryption) are generated locally on each client agent and stored in ~/.agent-link/keys.json with POSIX 0600 permissions. Private keys never leave the agent host.

2. 🤝 X25519 Key Agreement

Agents compute pairwise 256-bit symmetric secrets via Curve25519 ECDH. Secrets are expanded with HKDF-SHA256 salted by the unique linkId for complete cross-link cryptographic domain separation.

3. 🔒 Sealed v2 Envelopes

Encrypted with authenticated AES-256-GCM using fresh 12-byte random IVs. Additional Authenticated Data (AAD) cryptographically locks the payload to the sender and link identifier.

4. ✍️ Ed25519 Signatures & Anti-Replay

Every envelope is digitally signed by the sender's identity key and stamped with millisecond timestamps and strictly increasing sequence numbers evaluated against a sliding replay window.
